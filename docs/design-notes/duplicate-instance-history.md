# Duplicate instance history

Two or more processes sharing the same `instanceId`, racing to write the same heartbeat file and claim from the same drafting folder. Caused by a manual restart racing `queue-watchdog`'s automatic one; root-caused 2026-07-19 (see `docs/pipeline-incident-2026-07-19.md`) and **fixed in code** since 2026-08-16 — every spawn path (`local-worker`, `queue-watchdog`, `apply-runner`, `review-runner`, `queue-watcher`) now calls a startup liveness check (`check_instance_liveness` in `agent-manager-common.ps1`/`.sh`) that refuses to start under an `instanceId` a confirmed-alive process already holds, hardened twice more since (2026-08-22: pure pid-liveness instead of a heartbeat-staleness window that could wrongly call a slow-but-alive process dead; 2026-08-25: the surviving process claims its own heartbeat immediately on startup, before any slower setup work, closing the remaining window where a stale pre-restart heartbeat could fool a concurrent `dead-process-check` tick into spawning a replacement).

This entry was left stale after that fix landed and caused several redundant "still unfixed" tasks/brain-dump entries — if you're about to file one, check `git log --oneline -- src/agent-manager-common.ps1` for `check_instance_liveness` first.
